§1 — Project Overview

CreatorSync is a full-stack web application that lets social media content creators plan, schedule, and automatically publish posts across YouTube, Instagram, TikTok, and Twitter — all from one place, powered by an AI assistant (OpenAI GPT-4o-mini).

Problem Statement

Content creators manually manage 4+ social media platforms daily. There is no single tool that combines scheduling + AI content generation + multi-platform publishing. Time is wasted on repetitive tasks: writing captions, finding hashtags, switching between apps.

Solution

  • 📅 Visual Content Calendar — Plan posts with month/week/day views
  • 🤖 AI Assistant — Generate ideas, captions & hashtags using GPT-4o-mini
  • 🚀 Auto-Publisher — Schedule once, auto-publish to all platforms
  • 🔐 Secure Auth — JWT + bcrypt + Fernet-encrypted OAuth tokens

Out of Scope

  • Analytics dashboards
  • Team/collaboration features
  • Paid subscription billing
  • Mobile native apps

3 Core Data Flows

Flow 1 — Create & Schedule a Post

User fills PostForm (React)
  → POST /posts (Axios + JWT header)
    → posts router → PostService.create_post()
      → Insert Post row (status=scheduled)
      → SchedulerService.schedule_job(post)
    → Return Post JSON → React updates calendar

Flow 2 — Auto Publish at Scheduled Time

APScheduler fires job at scheduled_at
  → PublishService.publish_post(post_id)
    → Load Post + PlatformTokens from DB
    → For each platform in post.platforms:
        Publisher.publish(post, token) → Call Platform API
    → Update post.status = "published" or "failed"

Flow 3 — AI Caption Generation

User clicks "Generate Caption" in PostForm
  → POST /ai/caption { topic, platform }
    → AiService.generate_caption() → OpenAI API call
    → Return { caption: "..." }
  → React inserts caption into PostForm content field

§8 — Authentication Flow

Registration

POST /auth/register { email, password, display_name }
  → Validate email uniqueness
  → Hash password with bcrypt
  → Insert User row
  → Create JWT (HS256, 24h expiry, payload: { user_id, exp })
  → Return { user, access_token }

Login

POST /auth/login { email, password }
  → Load user by email
  → bcrypt.verify(password, hashed_password)
  → Create JWT
  → Return { user, access_token }

Protected Routes

Request with header: Authorization: Bearer <token>
  → get_current_user(token) dependency in auth_middleware.py
    → python-jose decodes JWT, extracts user_id
    → Load User from DB
    → Inject into route handler
Note: JWT is stored in localStorage on the frontend (acceptable for a student/demo project). For production, httpOnly cookies are more secure.

§9 — AI Integration

How It Works

  • Module: services/ai_service.py wraps the OpenAI Python SDK
  • Model used: gpt-4o-mini (cheap + fast)
  • Each function builds a system prompt + user prompt and calls the API
  • Responses are parsed and returned as structured JSON
  • Rate limited: 15 requests/minute/user to prevent OpenAI cost abuse

§10 — Publishing & Scheduler

Publisher Architecture

  • BasePublisher — abstract class with publish(post, token) method
  • Each platform has its own class: TwitterPublisher, InstagramPublisher, YouTubePublisher, TikTokPublisher
  • PublishService looks up which platforms a post targets and calls the right publisher
  • If one platform fails, others still get published — failure is isolated

APScheduler

  • Runs in-process inside FastAPI using lifespan events
  • On startup: loads all posts with status=scheduled and future scheduled_at, registers jobs
  • When a job fires: calls publish_service.publish_post(post_id)
  • Post status updated to published or failed in DB
  • Jobs are cancelled when a post is deleted or rescheduled

§14 — SIH Judge Q&A — Frontend

Q: Why did you use React over plain HTML/JS?
React's component model lets us reuse pieces like PostForm and AiSuggestionPanel across multiple pages without duplicating code. State management with useState and useContext keeps the UI automatically in sync with data.
Q: How does the frontend know if the user is logged in?
The JWT token is stored in localStorage. On every app load, AuthContext calls /auth/me to verify the token is still valid. If it fails, the user is logged out automatically and redirected to /login.
Q: What happens if the JWT token expires mid-session?
The Axios response interceptor in axiosClient.js catches any 401 response, clears the token from localStorage, and redirects to /login — all automatically without any extra code in the pages.
Q: How does AI-generated content get inserted into the post form?
AiSuggestionPanel receives an onUseCaption callback prop from PostForm. When the user clicks "Use This Caption", it calls that callback which updates the content field in the form's state via React's controlled component pattern.
Q: How is the calendar built?
We use the react-big-calendar library with a date-fns localizer. Posts with a scheduled_at date are converted into calendar events. Color-coding (yellow=scheduled, green=published, red=failed) is applied via eventStyleGetter based on post status.
Q: What is Tailwind CSS and why use it?
Tailwind CSS is a utility-first CSS framework. Styles are applied directly as class names like bg-white rounded-xl p-4 instead of writing separate CSS files. It speeds up UI development significantly and keeps styling consistent.
Q: How do you prevent unauthorized access to pages?
ProtectedRoute.jsx wraps all private pages. If no token exists in localStorage, it uses React Router's <Navigate> to redirect to /login before rendering anything.
Q: Is the frontend mobile responsive?
Yes. Tailwind's responsive prefixes (sm:, md:, lg:) are used throughout. The Navbar has a hamburger menu on mobile. The dashboard grid switches from 1 to 2 to 3 columns based on screen size using Tailwind grid classes.
Q: How does the frontend communicate with the backend?
All API calls go through axiosClient.js which is configured with VITE_API_URL as the base URL. The JWT token is automatically attached to every request via a request interceptor. Separate api/ modules (authApi, postsApi, etc.) keep API calls organized.
Q: What happens when the user submits an empty form?
validators.js runs client-side validation before any API call is made. Field-level error messages appear inline below each input (e.g. "Content is required.", "Select at least one platform."). The form does not submit until all validations pass.

§15 — SIH Judge Q&A — Backend

Q: Why FastAPI over Django or Flask?
FastAPI is async-first, auto-generates interactive API docs (Swagger at /docs), has built-in Pydantic validation, and is significantly faster than Flask. It's also more beginner-friendly than Django for API-only backends.
Q: How are passwords stored?
Passwords are hashed using bcrypt via the passlib library. Only the hash is stored in the database — the original password is never stored anywhere. On login, bcrypt.verify() compares the entered password against the stored hash.
Q: How does JWT authentication work?
On login, the backend creates a JWT signed with HS256 using a SECRET_KEY environment variable. The token contains user_id and an expiry (24h). Every protected route uses a FastAPI Depends(get_current_user) which decodes and validates the token from the Authorization header.
Q: How are platform OAuth tokens kept secure?
OAuth tokens (access_token, refresh_token) are encrypted using Fernet symmetric encryption from the cryptography library before being stored in the database. They are decrypted only when needed for publishing. The FERNET_KEY is stored only in environment variables.
Q: How does the background scheduler work?
APScheduler runs inside the FastAPI process. On startup (lifespan event), it loads all posts with status=scheduled and registers a job for each at their scheduled_at time. When a job fires, it calls publish_service.publish_post(). Jobs are cancelled on delete/reschedule.
Q: What happens if one platform fails to publish?
Each platform publisher is called independently. If one fails, the error is caught, the post's publish_error field is updated with the message, and publishing continues to the other platforms. A failure on TikTok does not stop Instagram from publishing.
Q: Why SQLite instead of PostgreSQL?
SQLite is zero-config and file-based — perfect for a single-server student project. The ORM (SQLAlchemy) abstracts the database, so migrating to PostgreSQL later only requires changing the DATABASE_URL environment variable.
Q: How is CORS configured?
In main.py, CORSMiddleware is configured to only allow requests from FRONTEND_URL (the deployed Render frontend URL). In development, localhost:5173 is also allowed. This prevents other websites from making API calls on behalf of users.

§16 — SIH Judge Q&A — General / Product

Q: What problem does CreatorSync solve?
Content creators waste 2-3 hours daily switching between multiple platforms, manually writing captions, and scheduling posts. CreatorSync centralizes everything — plan on the calendar, generate AI content, and auto-publish to all platforms from one tool.
Q: Who is your target user?
Social media content creators, especially India's 80M+ creator economy. From small individual creators to mid-size influencers who manage YouTube, Instagram, TikTok, and Twitter simultaneously.
Q: What is your innovation?
The combination of AI-powered content generation (GPT-4o-mini) directly integrated into the scheduling workflow. A creator can go from topic idea → AI-generated caption + hashtags → scheduled post → auto-published — all in one app without switching tools.
Q: How is this different from Buffer or Hootsuite?
Buffer and Hootsuite are expensive SaaS tools ($15-$99/month). CreatorSync is open-source and free to deploy. It also has built-in AI content generation which most basic tiers of those tools don't include.
Q: What is the future scope?
Analytics dashboard (views/likes/reach per post), team collaboration with approval workflows, native mobile app (React Native), support for LinkedIn/Pinterest, and a freemium SaaS model targeting the Indian creator economy.
Q: How would you scale this for millions of users?
Replace SQLite with PostgreSQL, move APScheduler to Celery + Redis for distributed task queuing, deploy backend as multiple instances behind a load balancer, and use a CDN for frontend assets. The SQLAlchemy ORM and FastAPI architecture support this migration without major rewrites.
Q: How did you test the application?
Backend: pytest with httpx TestClient — unit tests for services and integration tests for each router using an in-memory SQLite test DB. Frontend: Vitest + React Testing Library for validators and components. CI/CD: GitHub Actions runs all tests automatically on every push to main.
